# 26.11 Release notes (unreleased)

```{default-domain} nix
```

## Breaking changes

- If you specified `EPICS_PVA_ADDR_LIST` or related
  in your `environment.variables` NixOS options,
  it will lead to conflict with the new options
  in the {option}`environment.epics` module.
  Remove those variables
  and use {option}`environment.epics.pva_addr_list` and related options instead.

## New features and highlights

- New {option}`services.pva-gateway` NixOS module,
  which enables pvAccess clients from a network
  to access pvAccess IOCs on another network.
  See {doc}`../nixos-services/user-guides/pva-gateway` for how to set it up.

- New {option}`services.softIocs` NixOS module,
  which enables you to deploy SoftIOCs directly
  by specifying the database content,
  without having to create a full-blown traditional IOC.
  See {doc}`../nixos-services/user-guides/softioc-services` for how to set it up.

- The {option}`environment.epics` module now enables you
  to configure the address list for pvAccess.

- The {option}`services.iocs` module now checks
  if the specified {option}`~services.iocs.<name>.workingDirectory` exists
  in the IOC {option}`~services.iocs.<name>.package`
  during the NixOS build.
  This prevents deploying an IOC
  with a wrongly named {term}``iocBoot directory``.

- The `pcaspy` Python module is now packaged in EPNix,
  available as {pkg}`python3Packages.pcaspy`.

## Fixes

- Tomcat 9 applications,
  such as {option}`services.dbwr` and {option}`services.pvws`
  now uses the [{program}`tomcat-jakartaee-migration`] tool
  to convert their webapps to make them compatible with Tomcat 10+.

  This should fix using both {option}`services.archiver-appliance`
  and {option}`services.dbwr` or {option}`services.pvws`
  in the same NixOS configuration.

  This fix was backported to the `nixos-26.05` branch.

  [{program}`tomcat-jakartaee-migration`]: https://github.com/apache/tomcat-jakartaee-migration
